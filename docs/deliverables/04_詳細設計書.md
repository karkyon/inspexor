# 1. はじめに

## 1.1 本書の目的

本書は、基本設計書（SK-2026-08-MINI-03）にもとづき、データ項目・API・権限・業務の計算規則・帳票の値・セキュリティを、保守や将来の改修で参照できる粒度で定めます。

本書は技術者向けの内容を含みます。用語はできるだけ説明を添えています。

## 1.2 表記

| 表記 | 意味 |
|---|---|
| string(30) | 30文字までの文字列 |
| int | 整数 |
| bool | true／false |
| timestamp | 日時（世界標準時で保存し、画面では日本時間で表示） |
| date | 日付（YYYY-MM-DD、日本時間の業務日） |
| array | 配列（複数の値の並び） |
| map | 項目の入れ物（入れ子のデータ） |
| id | 文書を一意に表す番号（UUID：ランダムに作る36文字の識別子） |
| 必須 ○ | 必ず値が入る。× は空（null）を許す |

## 2.4 報告

### workReports・deliveryReports（報告のヘッダ）

作業日報（workReports）と運搬実績（deliveryReports）は同じ形のヘッダを持ちます。

| 項目 | 型 | 必須 | 内容 |
|---|---|---|---|

| status | string | ○ | DRAFT（下書き）／CONFIRMED（確定）／SUBMITTED（提出済）／DISCARDED（破棄。作業日報のみ）。承認・請求用の値（APPROVED 等）は今回使わない |
| inProgress | bool | ○ | 作業日報のみ。終わっていない従事行（endAt が null）がある下書きなら true。運搬実績は常に false |
| billOvertime | bool | ○ | 作業日報のみ。時間外を請求するか（初期値 false）。事務所の後入力（API-045）で更新し、版は作らない |
| ownerId | id | ○ | 報告者（報告の所有者）。代理入力では、選ばれた現場の利用者 |
| proxy | map | × | 代理入力のときだけ。enteredBy（入力した事務所の利用者）、enteredByName、reason（理由、500文字まで）、enteredAt |
| latestRevisionId / latestRevisionNo | id / int | ○ | 最新の版（修正中なら下書きの版） |
| currentRevisionId | id | × | 確定済みの現在の版。一度も確定していなければ null |
| businessDate | date | ○ | 一覧用: 最新の版の作業日・運搬日 |
| customerId | id | ○ | 一覧用: お客様 |
| productIds | array(id) | ○ | 一覧用: 品番（作業日報は品番の明細の品番、運搬は明細の品番。重複なし） |
| quantity | int | ○ | 一覧用: 作業日報は品番の明細の処理数量の合計（工程ごとの品番は仕上げ＋検査）、運搬は明細の合計 |
| tripCount | int | × | 一覧用: 運搬回数（作業日報は null） |
| deliveryFeeYen | int | × | 運搬費（0〜9,999,999円、運搬実績のみ）。null は未確定。事務所の後入力で更新し、版は作らない |
| workerIds / vehicleId / workLocationId / defectTypeIds | — | — | マスタの使用状況の確認用（最新の版の値。作業日報の workerIds は従事行の作業者） |
| documentId / documentStatus | id / string | × | 最新の版の帳票と、その状態 |
| current | map | × | 月次集計用: 確定済みの現在の版の要約（下表）。一度も確定していなければ null |
| submittedAt | timestamp | × | 帳票ができて提出済になった日時 |

current（作業日報、schemaVersion 2）: revisionId, revisionNo, schemaVersion, businessDate, customerId, workLocationId, moveCount, billOvertime（ヘッダの値の写し。API-045 で更新）, totals（版の totals と同じ）, items（品番の明細ごとの productId, workTypeId, lotNo, quantity, finishQuantity, inspectQuantity, defectQuantity, allocatedMinutes＝総作業時間を処理数量の比で分けた分）, laborSummary（作業者×検査区分×工程ごとの workedMinutes・overtimeMinutes・breakMinutes、array(map)）

current（作業日報、schemaVersion 1 の旧版）: revisionId, revisionNo, businessDate, customerId, productId, workTypeId, quantity, defectQuantity, actualMinutes, personMinutes。月次集計は旧版を items 1行・作業者不明の laborSummary（検査区分なし）として読む

current（運搬実績）: revisionId, revisionNo, businessDate, customerId, tripCount, items {productId, quantity}

修正中（最新の版が下書き）でも current は前の確定版のままなので、月次集計は前の確定版で数えます。

### workReports/{id}/revisions/{revisionId}（作業日報の版）

schemaVersion 2（本書 1.2 版の改修後に作成する版）の項目です。

| 項目 | 型 | 必須 | 内容 |
|---|---|---|---|
| schemaVersion | int | ○ | 2。項目がなければ 1（旧版、下表） |
| revisionNo | int | ○ | 版番号（1, 2, …） |
| parentRevisionId | id | × | 修正元の版 |
| confirmedAt | timestamp | × | 確定日時。確定前は null。確定後の版は書き換えない |
| workDate | date | ○ | 作業日 |
| reporterId | id | ○ | 報告者（利用者） |
| customerId | id | ○ | お客様 |
| items | array(map) | ○ | 品番の明細（1〜20行、lineNo 順）。{lineNo, productId, workTypeId, lotNo（string(100) か null）, quantity（int か null）, finishQuantity（int か null）, inspectQuantity（int か null）, defects: array(map){defectTypeId, quantity}（不良種別の表示順）, otherNote（string(20) か null）, inventory（在庫を管理する品番のみ、CHG-015）}。工程ごとに数量を入れる品番は quantity=null、それ以外は finishQuantity・inspectQuantity=null |
| laborLines | array(map) | ○ | 従事行（確定時は1〜100行。下書きは0行も可。開始時刻・作業者コード順）。{lineId（uuid）, workerId, isoCategory（INSPECTION／NON_INSPECTION）, stage（FINISH／INSPECT／null）, startAt, endAt（下書きは null 可）, breakMinutes, overtimeMinutes, workedMinutes（確定時に計算。下書きは null）, updatedBy, updatedAt} |
| totals | map | × | 確定時にサーバーで計算（下書きは null）。workedMinutes, inspectionMinutes, nonInspectionMinutes, finishMinutes, inspectStageMinutes, overtimeMinutes, breakMinutes, firstStartAt, lastEndAt |
| moveCount | int | × | 移動回数（0〜99）。作業場所がお客様の工場のときだけ |
| workLocationId / vehicleId | id | × | 作業場所・使用車 |
| remarks | string(500) | × | 備考 |

schemaVersion 1（旧版）は productId, workTypeId, lotNo, workerIds, startAt, endAt, breakMinutes, regularMinutes, overtimeMinutes, regularPersonMinutes, overtimePersonMinutes, quantity, defects を持ちます。読み取り専用で残し、画面・帳票は旧版の項目で表示します。旧版の報告を修正するときは、作業者ごとに同じ開始・終了・休憩の従事行（検査区分は作業内容の既定値、時間外は旧版の overtimeMinutes。各行に同じ値）と items 1行を作り、schemaVersion 2 の下書きにします。

## 2.6 補助・記録

| コレクション | 文書ID | 項目 | 用途 |
|---|---|---|---|
| uniqueKeys | {種類}:{範囲}:{値} | kind, scope, value, ownerId | 一意の保証（ログインID・マスタのコード等）。登録・コード変更と同じトランザクションで作成・付け替え |

## 2.7 検索用の索引（infra/firestore/firestore.indexes.json）

workReports・deliveryReports それぞれに次の5つの複合索引を持ちます。これに workReports の（inProgress, businessDate 降順, createdAt 降順）（作業中の日報）と、inventoryTxns の（productId, businessDate, createdAt）（在庫の動き、範囲外）を加えた計12件です。

| 項目の組み合わせ | 用途 |
|---|---|
| businessDate 降順, createdAt 降順 | 報告一覧（期間） |
| ownerId, businessDate 降順, createdAt 降順 | 現場の利用者の自分の報告 |
| productIds（配列の包含）, businessDate 降順, createdAt 降順 | 品番での絞り込み |
| customerId, businessDate 降順, createdAt 降順 | お客様での絞り込み |
| status, businessDate 降順, createdAt 降順 | 状態での絞り込み |

月次集計は current.businessDate の範囲で検索します（1項目の範囲検索のため複合索引は不要）。作業と運搬をまたぐ一覧の並べ替えは、両方を読んだ後にアプリで行います。idempotency.expiresAt に TTL を設定しています。

# 3. API 仕様

## 3.1 共通仕様

| 項目 | 内容 |
|---|---|
| 基本 URL | /api/v1 |
| 形式 | JSON（UTF-8）。日時は ISO 8601（世界標準時）、日付は YYYY-MM-DD |
| 認証 | ログインで発行する Cookie `__Secure-inspexor.session` |

| 冪等性 | 確定・帳票操作は `Idempotency-Key` ヘッダ（16〜100文字）が必須。同じキーと内容なら前回の結果を返す。キーが同じで内容が違えば 409 |

| 追跡番号 | 応答ヘッダ `X-Correlation-Id`。障害調査に使う |

# 5. 業務の計算規則

## 5.1 時間の計算（従事行）

| 規則 | 内容 |
|---|---|
| 刻み | 開始・終了・休憩・時間外は5分刻み。保存は分（整数） |
| 範囲 | 開始は作業日の日本時間。終了は開始より後で、翌日0:00まで（日をまたぐ作業は不可。cross_day） |
| 行の実作業時間 | 終了 − 開始 − 休憩（workedMinutes）。休憩は0以上・終了−開始未満（break_exceeds） |
| 時間外 | 手入力。0以上・行の実作業時間以下（overtime_exceeds） |
| 重なり | 同じ作業者の行どうしで [開始, 終了) が重なってはいけない（labor_overlap）。終了が空の行は終了を無限大として扱う |
| 行数 | 確定時 1〜100（labor_lines_range）、下書き 0〜100 |
| 工程 | 品番の stageType が FINISH_INSPECT なら stage 必須（stage_required）、NONE なら null。isoCategory は stage が FINISH なら NON_INSPECTION、INSPECT なら INSPECTION に揃える |
| 総作業時間 | 全行の workedMinutes の合計（totals.workedMinutes） |
| 割増作業時間 | billOvertime が true なら totals.overtimeMinutes、false なら0（月次集計・請求で使う） |
| 時間の表示 | 分÷60 を小数2桁に四捨五入（例 115分→1.92H、230分→3.83H） |
| 開始・終了ボタン | 画面で現在時刻を近い方の5分に丸める（2分30秒は切り上げ）。サーバーは5分刻みであることだけを検査する |

目安（画面の表示だけ。保存しない）: 休憩は 12:00〜13:00 と行の重なり（休憩0分のとき表示）、時間外は平日の17:00以降と、土日・休日マスタの日の行の時間。計算は packages/domain の computeBusinessTime を目安用に残して使う。

確定時に、サーバーで全行を検証し totals を計算して保存します（休日マスタは使いません）。

## 5.2 報告番号

- 形式: 種別（WR／DR）-年月（YYYYMM）-連番6桁。年月は登録日（日本時間）の年月。
- counters の文書（例 WR-202610）の value をトランザクションで +1 して採番し、月が変われば1から。

## 5.3 月次集計

- 対象: current.businessDate が指定月の1日〜末日の報告（確定済みの現在の版）。DISCARDED は含めない。
- 作業の時間: totals と laborSummary を使う。品番別・作業内容別・品番日別の時間は items[].allocatedMinutes（報告の総作業時間を処理数量の比で分け、分の端数は最初の行。処理数量の合計が0なら最初の行に全部）。
- 作業者別: laborSummary を作業者×検査区分×工程で合計し、作業日数（その作業者の行がある作業日の数）を数える。
- 品番日別: 絞り込んだ品番（指定がなければ対象の全品番）ごとに、月の全日の行を作る。
- 運搬数量: 品番を指定した場合は、その品番の明細の数量だけを数える（運搬回数・運搬費は報告単位）。
- 運搬費: 入力された金額の合計と、未入力（null）の件数。
- 並び: 日付、同じ日は報告番号の順。
- CSV: UTF-8（BOM 付き）、改行 CRLF、`= + - @` で始まる文字は先頭に `'` を付けて数式として扱われないようにする。

# 6. 帳票の値の出所

## 5.4 品番の明細の規則（CHG-017）

| 規則 | エラーの code |
|---|---|
| 1〜20行 | items_range |
| 品番は選んだお客様の有効な品番、作業内容はその品番の有効な作業内容 | mismatch／MASTER_INACTIVE |
| 同じ品番・同じロットNo の行は1つ | item_duplicate_lot |
| 1件の中の品番は同じ精算区分 | item_settlement_mixed |
| 時間で精算する品番は1件に1品番（ロットごとの行は可） | item_time_multiple |
| 1件の中の品番は同じ stageType | item_stage_mixed |
| quantityByStage の品番は finishQuantity・inspectQuantity（0〜999,999）、それ以外は quantity（0〜999,999） | range／stage_quantity |
| 不良種別はその品番のもの、重複不可。合計は quantity（工程ごとは大きい方）以下 | mismatch／duplicate／exceeds_quantity |
| otherNote は20文字まで。品番に名称「その他」の有効な不良種別があり、その個数が1以上のときだけ | other_note_without_other |
| ロット必須の品番は lotNo 必須 | required |
| 処理数量 | quantityByStage なら finishQuantity＋inspectQuantity、それ以外は quantity |

## 5.5 在庫の計算（CHG-015、範囲外）

| 出来事 | 預かり在庫（lots） | 調整用在庫 |
|---|---|---|
| 検品（作業日報の確定） | 名目数＝boxCount×unitsPerBox の検品ロット（lotDate＝作業日）を追加 | − 不良合計 − shortage ＋ surplus（shortage・surplus は選別数量と名目数の差） |
| 1箱回す | その日の検品ロット（無ければ最も新しいロット）から − unitsPerBox×箱数 | ＋ 同じ数 |
| 納入 | 古いロットから − 納入数。足りなければ 422 inventory_insufficient | — |
| 棚卸 | 数えた数との差（古いロットから減らす／その日のロットとして増やす） | 数えた数との差 |
| 修正の確定 | 前の版の動きを打ち消す REVERSAL を記録してから新しい版の動きを記録 | 同左 |

1件の作業日報の確定で、検品 → 1箱回す → 納入の順に記録します（当日分を同日に納入できる）。boxCount の初期値は選別数量÷入数の四捨五入。調整用在庫を管理しない品番（adjustStockManaged=false）は調整用在庫を動かしません。

# 7. セキュリティの詳細

| 項目 | 設定値 |
|---|---|
| パスワード | 利用者管理で設定するパスワードは12〜128文字。Argon2id で保存し、画面・記録には出さない |
| ロック | 連続5回の失敗で15分 |
| 回数の制限 | 7.1 のとおり。上限を超えた要求はパスワードを照合しない（ロックの回数も増えない） |
| 本人確認 | 代理入力・パスワード再設定などの前に、直近10分以内のログインまたは本人確認（API-040）が必要 |
| ログイン状態 | 署名付き Cookie（HMAC-SHA256）。HttpOnly・Secure・SameSite=Lax・Path=/。無操作30分、最長12時間。操作のたびに無操作の期限を延長 |
| ログイン状態の即時無効化 | 利用停止・区分変更・パスワード再設定をすると、それより前のログイン状態を無効にする（各サーバーで最大30秒の遅れ） |
| 管理不能の防止 | 自分自身の利用停止・自分の管理者区分の削除・有効な管理者が0人になる変更はできない |
| CSRF | ログインごとのトークン（乱数＋HMAC）。GET 以外で必須 |
| 権限の確認 | API の入口で区分を確認し、現場の利用者は対象の報告が本人のものか読み込み後に確認 |
| PDF のリンク | ファイルID＋期限（10分）に HMAC 署名。期限切れ・改ざんは表示しない |
| ファイル名 | パス区切り・制御文字・使えない文字を除去 |
| エラー表示 | 想定外のエラーは内部の詳細を返さず、追跡番号のみ返す |
| 鍵 | AUTH_SECRET（32バイト以上の乱数）は Secret Manager に保管 |
| 保存場所 | Firestore・Cloud Storage は東京リージョン。Cloud Storage は一般公開を禁止 |
| 管理者の多要素認証 | 本番では無効（8章 ADMIN_MFA_ENABLED）。有効にすると、管理者は認証アプリの確認コード（30秒・6桁）でもログインし、回復コード10個を一度だけ表示する |

## 7.1 回数の制限

| 対象 | 上限 | 数え方 |
|---|---|---|
| ログイン・確認コード・本人確認（接続元ごと） | 10分に100回 | Firestore の rateLimits（複数のサーバーで共有）。接続元は Cloud Run が付ける X-Forwarded-For の末尾 |
| 同（ログインID・利用者ごと） | 10分に30回 | 同上 |
| 更新の API（利用者ごと） | 1分に120回 | サーバーごとのメモリ |
| 参照の API（利用者ごと） | 1分に600回 | 同上 |

上限は通常の操作では届かない値です。運用で調整する場合は packages/domain/src/security-policy.ts を変更します。
