# 1. はじめに

## 1.1 本書の目的

本書は、基本設計書（SK-2026-08-MINI-03）にもとづき、データ項目・API・権限・業務の計算規則・帳票の値・セキュリティを、保守や将来の改修で参照できる粒度で定めます。

本書は技術者向けの内容を含みます。用語はできるだけ説明を添えています。

## 1.2 表記

| 表記 | 意味 |
|---|---|
| string(30) | 30文字までの文字列 |
| int | 整数 |
| bool | true／false |

## 2.4 報告

### workReports・deliveryReports（報告のヘッダ）

作業日報（workReports）と運搬実績（deliveryReports）は同じ形のヘッダを持ちます。

| 項目 | 型 | 必須 | 内容 |
|---|---|---|---|
| reportNo | string | ○ | 報告番号。作業日報 WR-YYYYMM-NNNNNN、運搬実績 DR-YYYYMM-NNNNNN。一意 |
| status | string | ○ | DRAFT（下書き）／CONFIRMED（確定）／SUBMITTED（提出済）。承認・請求用の値（APPROVED 等）は今回使わない |
| ownerId | id | ○ | 登録した利用者 |
| latestRevisionId / latestRevisionNo | id / int | ○ | 最新の版（修正中なら下書きの版） |
| currentRevisionId | id | × | 確定済みの現在の版。一度も確定していなければ null |
| businessDate | date | ○ | 一覧用: 最新の版の作業日・運搬日 |
| customerId | id | ○ | 一覧用: お客様 |
| productIds | array(id) | ○ | 一覧用: 品番（作業日報は1件、運搬は明細の品番） |
| quantity | int | ○ | 一覧用: 作業数量、運搬は明細の合計 |
| tripCount | int | × | 一覧用: 運搬回数（作業日報は null） |
| deliveryFeeYen | int | × | 運搬費（0〜9,999,999円、運搬実績のみ）。null は未確定。事務所の後入力で更新し、版は作らない |
| workerIds / vehicleId / workLocationId / defectTypeIds | — | — | マスタの使用状況の確認用（最新の版の値） |
| documentId / documentStatus | id / string | × | 最新の版の帳票と、その状態 |
| current | map | × | 月次集計用: 確定済みの現在の版の要約（下表）。一度も確定していなければ null |
| submittedAt | timestamp | × | 帳票ができて提出済になった日時 |

current（作業日報）: revisionId, revisionNo, businessDate, customerId, productId, workTypeId, quantity, defectQuantity, actualMinutes（実作業時間・分）, personMinutes（総作業時間・分）

修正中（最新の版が下書き）でも current は前の確定版のままなので、月次集計は前の確定版で数えます。

## 2.6 補助・記録

| コレクション | 文書ID | 項目 | 用途 |
|---|---|---|---|
| uniqueKeys | {種類}:{範囲}:{値} | kind, scope, value, ownerId | 一意の保証（ログインID・マスタのコード等）。登録・コード変更と同じトランザクションで作成・付け替え |
| counters | WR-202610 など | value | 報告番号の採番。トランザクションで +1 |
| idempotency | 利用者・経路・要求番号から作る値 | actorId, route, key, requestHash, status, responseStatus, responseJson, expiresAt | 二重送信の防止。expiresAt（24時間後）を過ぎると TTL（期限で自動削除する機能）で削除 |
| auditEvents | id | actorId, action, targetType, targetId, beforeJson, afterJson, reason, correlationId, occurredAt | 変更の記録。追加のみ |
| mailJobs | id | — | メール送信用。今回は使わない |

入れ子の配列を持てない Firestore の制約のため、変更前後の値・処理の値は JSON 文字列で保存します。

| action | 内容 |

## 2.7 検索用の索引（infra/firestore/firestore.indexes.json）

workReports・deliveryReports それぞれに次の5つ（計10件）の複合索引を持ちます。

| 項目の組み合わせ | 用途 |
|---|---|
| businessDate 降順, createdAt 降順 | 報告一覧（期間） |
| ownerId, businessDate 降順, createdAt 降順 | 現場の利用者の自分の報告 |
| productIds（配列の包含）, businessDate 降順, createdAt 降順 | 品番での絞り込み |
| customerId, businessDate 降順, createdAt 降順 | お客様での絞り込み |
| status, businessDate 降順, createdAt 降順 | 状態での絞り込み |

月次集計は current.businessDate の範囲で検索します（1項目の範囲検索のため複合索引は不要）。作業と運搬をまたぐ一覧の並べ替えは、両方を読んだ後にアプリで行います。idempotency.expiresAt に TTL を設定しています。

## 2.8 アクセス制御（Security Rules）

Firestore と Cloud Storage は、ブラウザから直接読み書きできないようにします（infra/firestore/firestore.rules で全面禁止）。読み書きは Cloud Run の実行用アカウント（サービスアカウント）からだけ行い、権限の確認はすべてサーバー側で行います。

| 実行用アカウント | 許可 |
|---|---|
| inspexor-web | Firestore の読み書き、帳票の読み出し、鍵の読み出し |
| inspexor-worker | Firestore の読み書き、帳票の保存 |
| inspexor-scheduler | 帳票作成の起動、Firestore の書き出し（バックアップ） |
| inspexor-build | プログラムのイメージ作成 |


# 3. API 仕様

## 3.1 共通仕様

| 項目 | 内容 |
|---|---|
| 基本 URL | /api/v1 |
| 形式 | JSON（UTF-8）。日時は ISO 8601（世界標準時）、日付は YYYY-MM-DD |
| 認証 | ログインで発行する Cookie `__Secure-inspexor.session` |
| CSRF | GET 以外は、ログイン時に受け取ったトークンを `X-CSRF-Token` ヘッダに付ける。無い・違う場合は 403 |
| 冪等性 | 確定・帳票操作は `Idempotency-Key` ヘッダ（16〜100文字）が必須。同じキーと内容なら前回の結果を返す。キーが同じで内容が違えば 409 |
| 同時更新 | 更新・確定は `expectedVersion`（画面が読んだ version）を送る。違えば 409 VERSION_CONFLICT |
| 追跡番号 | 応答ヘッダ `X-Correlation-Id`。障害調査に使う |
| 成功時の形 | `{ "data": …, "meta": … }` |
| 失敗時の形 | `{ "error": { "code", "message", "correlationId", "retryable", "fields": [{ "path", "code", "message" }] } }` |
| 一覧 | page（1〜）、pageSize（1〜100、初期値25） |
| 正式な定義 | docs/spec/openapi.yaml（OpenAPI 3.1、版 3.1.0-CHG-004） |

## 3.2 エラーコード

| code | HTTP | 意味 |
|---|---|---|
| AUTH_REQUIRED | 401 | ログインしていない、またはログインの期限切れ |
| FORBIDDEN | 403 | 権限がない |
| CSRF_INVALID | 403 | CSRF トークンがない・違う |
| ACCOUNT_LOCKED | 423 | ログインのロック中 |
| VALIDATION_ERROR | 422 | 入力の誤り（fields に項目ごとの理由） |
| MASTER_INACTIVE | 422 | 無効なマスタが選ばれた |
| VERSION_CONFLICT | 409 | 他の人が先に更新した |
| STATE_CONFLICT | 409 | 今の状態ではできない操作（確定済みの報告の変更など） |
| IDEMPOTENCY_CONFLICT | 409 | 同じ要求番号で内容の違う要求 |
| DEPENDENCY_UNAVAILABLE | 503 | クラウドの機能が一時的に使えない（やり直し可） |
| INTERNAL_ERROR | 500 | 想定外のエラー（詳細は返さず、記録に残す） |

# 5. 業務の計算規則

## 5.1 時間の計算

| 規則 | 内容 |
|---|---|
| 刻み | 開始・終了は5分刻み。保存は分（整数） |
| 範囲 | 開始は作業日の日本時間。終了は開始より後で、翌日0:00まで（日をまたぐ作業は不可） |
| 休憩 | 12:00〜13:00 と作業時間の重なる分 |
| 時間外 | 平日の17:00以降と、土日・休日マスタの日は全時間を時間外とする（画面・データの参考値。請求計算には使わない） |
| 実作業時間 | 通常時間＋時間外（休憩控除後） |
| 総作業時間 | 実作業時間×作業者数 |
| 時間の表示 | 分÷60 を小数2桁に四捨五入（例 115分→1.92H、230分→3.83H） |

確定時に、サーバーで休日マスタを含めて計算し直した値を保存します。

## 5.2 報告番号

- 形式: 種別（WR／DR）-年月（YYYYMM）-連番6桁。年月は登録日（日本時間）の年月。
- counters の文書（例 WR-202610）の value をトランザクションで +1 して採番し、月が変われば1から。

## 5.3 月次集計

- 対象: current.businessDate が指定月の1日〜末日の報告（確定済みの現在の版）。
- 運搬数量: 品番を指定した場合は、その品番の明細の数量だけを数える（運搬回数・運搬費は報告単位）。
- 運搬費: 入力された金額の合計と、未入力（null）の件数。
- 並び: 日付、同じ日は報告番号の順。
- CSV: UTF-8（BOM 付き）、改行 CRLF、`= + - @` で始まる文字は先頭に `'` を付けて数式として扱われないようにする。

# 7. セキュリティの詳細

| 項目 | 設定値 |
|---|---|
| パスワード | 利用者管理で設定するパスワードは12〜128文字。Argon2id で保存し、画面・記録には出さない |
| ロック | 連続5回の失敗で15分 |
| ログイン状態 | 署名付き Cookie（HMAC-SHA256）。HttpOnly・Secure・SameSite=Lax・Path=/。無操作30分、最長12時間。操作のたびに無操作の期限を延長 |
| ログイン状態の即時無効化 | 利用停止・区分変更・パスワード再設定をすると、それより前のログイン状態を無効にする（各サーバーで最大30秒の遅れ） |
| 管理不能の防止 | 自分自身の利用停止・自分の管理者区分の削除・有効な管理者が0人になる変更はできない |
| CSRF | ログインごとのトークン（乱数＋HMAC）。GET 以外で必須 |
| 権限の確認 | API の入口で区分を確認し、現場の利用者は対象の報告が本人のものか読み込み後に確認 |
| PDF のリンク | ファイルID＋期限（10分）に HMAC 署名。期限切れ・改ざんは表示しない |
| ファイル名 | パス区切り・制御文字・使えない文字を除去 |
| エラー表示 | 想定外のエラーは内部の詳細を返さず、追跡番号のみ返す |
| 鍵 | AUTH_SECRET（32バイト以上の乱数）は Secret Manager に保管 |
| 保存場所 | Firestore・Cloud Storage は東京リージョン。Cloud Storage は一般公開を禁止 |
