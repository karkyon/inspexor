# 1. この手順書の目的

テスト（試作版のご確認・現場テスト・試験運用）に使うデータと、本稼働で使うマスタ（お客様・品番・作業者など）・利用者を、Excel から一括で登録する方法と、テストが終わったあとに試験用のデータを取り除く方法を説明します。作業は当方が行います（お客様にお願いするのは、Excel への記入だけです）。

## 1.1 どの段階で、どのデータを使うか

| 段階（テスト計画書） | 環境 | 使うデータ | この手順書の章 |
|---|---|---|---|
| T3a 試作版のご確認 | 本番環境（本稼働前） | 試験用データ一式（コードが TEST- で始まるお客様・品番・作業者・利用者）と、試験用の報告 | 3・4 |
| T4 本番環境の確認 | 本番環境 | 同上 | 3・4 |
| T5 現場テスト | 本番環境 | 試験用データ一式（現場の方が実際の作業を TEST- のお客様で入力） | 3 |
| T5 の後・T6 の前 | 本番環境 | 試験用データを取り除く | 5 |
| T6 試験運用・本稼働 | 本番環境 | 実際のマスタ・利用者（お客様にご記入いただいた Excel） | 3 |

試験用のデータは、コードを必ず TEST- で始めます。実際のデータと区別でき、月次集計ではお客様を指定すれば除けます。T5 の後に、TEST- のデータだけを取り除きます（5章）。

## 1.2 使うもの

| もの | 内容 |
|---|---|
| マスタ登録テンプレート（Excel） | 記入用。「記入方法」シートと、お客様・品番・作業内容・不良種別・作業者・車両・作業場所・お客様担当者・休日・利用者のシート（請求機能用の単価・運搬ルール・固定費のシートもあります） |
| 試験用データ一式（Excel） | テンプレートに試験用のデータを記入済みのもの（お客様2社・品番5件・作業者5名・車両2台・作業場所2か所・担当者2名・利用者3名） |
| 当方の作業環境 | Google Cloud の Cloud Shell（INSPEXOR のプログラム一式と、本番・開発の権限） |

# 2. Excel の書き方

1. 1行目の見出しは変えないでください。2行目から、1行に1件を記入します。空の行は読み飛ばします。
2. （必須）の付いた列は必ず記入します。
3. お客様・品番などの「親」は、コードで指定します（例: 品番シートの「お客様コード」に TEST-C01）。登録はシートの並び順（お客様 → 品番 → 作業内容 → 不良種別 → …）で行うので、同じ Excel の中で親と子を一度に登録できます。
4. 「有効」「ロット必須」などは ○ または × を選びます（空欄は既定値）。「精算区分」は 数量／時間 を選びます。
5. 日付は 2026/12/01 のように書きます。締め日の月末は 31 または「末」です。
6. 既にあるコードの行は、内容が違えば更新、同じなら変更なしになります。削除はしません。使わなくなったものは「有効」を × にします（無効化）。
7. 利用者のシートは追加だけです。既にあるログインIDは変更しません（区分の変更は利用者管理の画面で行います）。初期パスワードは登録時に別ファイルに出力され、画面やメールには出しません。

# 3. マスタ・利用者の一括登録（当方の作業）

Cloud Shell で `~/inspexor/apps/web` に移動して行います。本番に登録するときは、環境の設定を本番にします。

```bash
cd ~/inspexor/apps/web
# 本番に登録するとき（開発は --env-file=.env.local を使う）
export APP_ENV=prod FIRESTORE_PROJECT_ID=inspexor-jadeworks-prod GOOGLE_CLOUD_QUOTA_PROJECT=inspexor-jadeworks-prod
```

## 3.1 Excel を用意する

```bash
npx tsx scripts/masters-template.ts ~/マスタ登録テンプレート.xlsx          # 記入用
npx tsx scripts/masters-template.ts ~/試験用データ一式.xlsx --sample        # 試験用データ一式
```

記入用はお客様にお渡しし、実際のマスタ・利用者をご記入いただきます。

## 3.2 確認する（書き込まない）

```bash
npx tsx scripts/import-masters.ts ~/試験用データ一式.xlsx --actor admin
```

行ごとに「追加・更新・変更なし・エラー」と、最後に件数を表示します。エラーが1件でもあれば、何も登録しません。表示された「シート名・行番号・理由」に従って Excel を直し、もう一度確認します。

| よくあるエラー | 直し方 |
|---|---|
| お客様コード「…」がありません | お客様シートにそのコードの行を追加するか、コードの書き間違いを直す |
| 「精算区分」は 数量・時間 のどれかです | 選択肢から選び直す |
| 同じシートに同じキーの行が2回あります | 重複している行の片方を消す |
| 適用期間が、同じ品番・作業内容の有効なルールと重なっています | 既存のルールの「適用終了」を設定してから登録する |

## 3.3 登録する

```bash
npx tsx scripts/import-masters.ts ~/試験用データ一式.xlsx --actor admin --apply --reason "試験用データ一式の登録" --prod
```

- 本番では `--prod` を付けないと登録できません（誤って本番に書き込まないため）。
- 既にある行を更新するときの理由（--reason）は、変更の記録に残ります。
- 登録は画面と同じ規則で行い、1件ずつ変更の記録（実行者は --actor の管理者）に残ります。

## 3.4 利用者の初期パスワード

利用者を追加すると、初期パスワードを `~/inspexor-initial-passwords-日時.csv`（当方だけが読める設定）に保存します。表示はしません。

1. ファイルを開き、本人に電話・手渡しなど、メールとは別の方法で伝えます。
2. 伝え終わったらファイルを削除します（`rm ~/inspexor-initial-passwords-*.csv`）。
3. 管理者の区分の利用者は、多要素認証を有効にしている場合、初回ログインで認証アプリの登録が必要です（操作マニュアル）。

# 4. 試験用の報告データの作成（当方の作業）

試作版のご確認や月次集計の確認のために、試験用のお客様（TEST-）で作業日報・運搬実績を期間を指定して作り、確定します。日報PDFは、確定のあと自動で作られます。

```bash
npx tsx scripts/seed-test-reports.ts --from 2026-12-01 --to 2026-12-14 \
  --customers TEST-C01,TEST-C02 --reporter test.field01 --work-per-day 3 --delivery-per-day 1 --prod
```

| 指定 | 内容 |
|---|---|
| --from / --to | 期間（93日まで）。日曜は作りません |
| --customers | お客様コード（本番では TEST- で始まるものだけ） |
| --reporter | 報告者（現場の区分の利用者のログインID） |
| --work-per-day / --delivery-per-day | 1日あたりの件数（既定 3 件・1 件） |
| --seed | 乱数の種。同じ値なら同じ内容になります |
| --draft | 確定せず下書きのままにする |

内容は、昼休憩をまたぐ作業・残業・複数の作業者・不良あり／なし・ロット番号・作業場所・車両・運搬費あり／空欄を混ぜた、現実に近いものです。報告番号は作業日の月で付きます。

作成後、画面で次を確認します: 報告一覧に出ること、日報PDFが作られていること、月次集計（お客様を TEST- で指定）の件数・数量。

# 5. テスト後の後片付け（T5 の後、T6 の前）

本番に入れた試験用のデータを取り除きます。

## 5.1 確認する

```bash
npx tsx scripts/purge-test-data.ts --actor admin --users test.
```

対象のお客様、削除する報告の件数、無効化するマスタ、利用停止する利用者を表示します（何も変えません）。

## 5.2 実行する

```bash
npx tsx scripts/purge-test-data.ts --actor admin --users test. --apply --reason "T5 現場テストの後片付け" --prod
```

| 内容 | 扱い |
|---|---|
| TEST- のお客様の作業日報・運搬実績（版・帳票の記録・送信の依頼を含む） | 削除する |
| TEST- のお客様・品番・作業内容・不良種別・担当者・作業者・車両・作業場所 | 無効化する（記録は残り、画面の選択肢から外れる） |
| ログインIDが test. で始まる利用者（管理者を除く） | 利用停止にする |
| 変更の記録（監査） | 消さない。後片付けそのものも記録（TEST_DATA_PURGE）に残る |
| 請求確定済みの報告がある場合 | 中止する（先に請求書を無効化する） |
| 報告番号 | 採番は続きから（試験で使った番号は欠番になる） |

## 5.3 帳票の PDF を消す

後片付けを実行すると、試験用の報告の PDF の保存先の一覧を `~/inspexor-test-pdf-keys-日付.txt` に書き出します。次のコマンドで消します。

```bash
while read -r key; do gcloud storage rm "gs://inspexor-jadeworks-prod-documents/$key"; done < ~/inspexor-test-pdf-keys-*.txt
rm ~/inspexor-test-pdf-keys-*.txt
```

# 6. 開発環境での練習

開発環境（inspexor-jadeworks-dev）では、`--env-file=.env.local` を付けて同じ手順を実行できます（`--prod` は不要）。プログラムを更新したときの確認作業（バッチ）でも、試験用データ一式の登録 → 報告データの作成 → 後片付けを毎回実行して、手順が動くことを確かめています。
