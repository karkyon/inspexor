## 1. API

| API | 内容 | 権限 |
|---|---|---|
| API-030 `GET /users` | 一覧（ログインID順。状態・ロック中を含む） | OFFICE / ADMIN / AUDITOR |
| API-031 `POST /users` | 作成（ログインID・表示名・ロール・初期パスワード 12〜128 文字）。ログインID重複は 422 | ADMIN |
| API-032 `PATCH /users/{id}` | 表示名・ロールの変更（expectedVersion） | ADMIN |
| API-033 `POST /users/{id}/{action}` | `deactivate` / `activate` / `reset-password`（新しいパスワード必須）/ `unlock`。理由は任意（監査に残る） | ADMIN |

- ログインID は変更不可（uniqueKeys `login` で一意）。利用者は削除せず無効化する（報告・監査の参照を保つ）
- パスワードは Argon2id のハッシュだけを保存し、応答・監査に出さない
- 自分自身の無効化・自分の ADMIN 外し、有効な ADMIN が 0 人になる変更は 422（管理不能を防ぐ）
- 監査: `USER_CREATE` / `USER_UPDATE` / `USER_DEACTIVATE` / `USER_ACTIVATE` / `USER_RESET_PASSWORD` / `USER_UNLOCK`

## 2. セッションの即時無効化

セッション token は署名のみで状態を持たないため、これまでは無効化・ロール変更をしても token の期限（最長12時間）まで使えた。
利用者の文書に `authChangedAt`（無効化・ロール変更・パスワード再設定の日時）を持ち、API の入口（`createApiHandler`）と `GET /me` で
「利用者が有効」かつ「セッションの発行が authChangedAt 以降」であることを確認する（`lib/auth/user-guard.ts`）。
Firestore の読込を減らすため process 内で 30 秒キャッシュし、同じ process で変更したときは即時に破棄する（他の instance では最大 30 秒遅れる）。

## 3. 画面（`/admin/users`）

一覧（検索・状態・ロック中）、追加（パスワードの自動生成・表示）、詳細（表示名・ロール、パスワード再設定、ロック解除、無効化・有効化）。OFFICE / AUDITOR は参照のみ。左ナビ「利用者管理」。

## 4. 検証

- web integration（`lib/users/users.itest.ts`）: 作成（パスワードを応答・監査に出さない、重複・短いパスワード・未知の項目は 422）、権限、ロール変更でセッション無効、無効化・有効化、パスワード再設定・ロック解除、自分・最後の ADMIN の保護
- E2E（`e2e/users.e2e.ts`）: 追加 → 新しい利用者でログイン → ロール変更で再ログインが必要 → 無効化でログイン不可 → 有効化・パスワード再設定 → 新しいパスワードでログイン
