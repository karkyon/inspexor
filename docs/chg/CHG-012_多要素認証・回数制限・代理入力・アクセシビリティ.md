## 1. 変更内容

### 1.1 ログインの回数制限（SEC-009 / GAP-010）

| 区分 | 上限 | 数え方 |
|---|---|---|
| ログイン・確認コード・再認証（接続元） | 10分に100回 | Firestore `rateLimits`（複数の実行環境で共有。TTL `expiresAt` で自動削除）。接続元は X-Forwarded-For の末尾（Cloud Run が付ける値） |
| 同（ログインID・確認待ち・利用者） | 10分に30回 | 同上。キーは sha256 で保存（ログインID・IP を残さない） |
| 更新 API（利用者ごと） | 1分に120回 | 実行環境ごとのメモリ |
| 参照 API（利用者ごと） | 1分に600回 | 同上 |

超えたら 429 `RATE_LIMITED`（`Retry-After` 秒、`retryAfterSeconds`）。回数制限で拒否したときはパスワードを照合しない（ロックの回数も増えない）。パスワードの誤りは従来どおり5回で15分ロック（SEC-003）。

### 1.2 管理者の多要素認証（SEC-004 / G1-03）— `ADMIN_MFA_ENABLED=true` のときだけ

- 方式: TOTP（RFC 6238、30秒・6桁・HMAC-SHA1）。Google Authenticator / Microsoft Authenticator などの認証アプリで使える。前後1区間（±30秒）まで許し、使った区間は再利用できない
- ログイン: パスワードが正しい管理者には session を出さず「確認待ち」（5分、署名付き）を返す → 確認コードで session（`mfa: true`）。未登録なら QR コード（と手入力用の秘密鍵）で登録 → 回復コード10個を一度だけ表示（保存の確認チェック後に進む）
- 回復コード: XXXX-XXXX、各1回。使用時に監査（残り数）。アカウント画面（`/admin/account`）で再発行（再認証が必要、古いコードは無効）
- 保存: 秘密鍵は AES-256-GCM で暗号化、回復コードは HMAC。鍵は AUTH_SECRET から用途別に導出。秘密鍵・コードは応答（登録時を除く）・記録に出さない
- 確認コードの誤りはパスワードの誤りと同じく数え、5回でロック。パスワードだけでは失敗回数を戻さない（確認コードを何度でも試せないように）
- 機能を有効にする前の管理者の session、確認コードを済ませていない管理者の session は使えない（再ログインが必要）
- 解除: 管理者が利用者管理で他の管理者の多要素認証を解除（理由必須、自分は不可、再認証が必要）→ 対象の session は無効、次のログインで登録し直す。全員が使えなくなったときは運用担当が `apps/web/scripts/reset-mfa.ts` で解除（監査に残る）
- 監査: MFA_ENROLL / MFA_RECOVERY_USED / MFA_RECOVERY_REGENERATE / USER_RESET_MFA / REAUTHENTICATE

### 1.3 再認証（SEC-026）

代理入力・パスワード再設定・多要素認証の解除・回復コードの再発行は、直近10分以内の認証（ログインまたは再認証）が必要。過ぎていれば 403（`reauthRequired: true`）を返し、画面は「本人確認」ダイアログ（パスワード＋登録者は確認コード）を開いて、同じ操作を1回だけ送り直す。

### 1.4 代理入力（SPEC-CONFLICT-G3-01）

- 事務所（OFFICE）は新しい作業日報で、有効な現場（FIELD）の利用者を報告者に選べる（画面: 報告者の選択 →「代理入力の理由」必須）
- API: `POST /work-reports` の `proxyReason`（作成時のみ、500文字まで）。報告者が本人以外なら必須、本人なら指定不可。現場ロールの代理は 422 `proxy_not_allowed`
- 報告者が所有者になり、本人の現場ホーム・報告一覧に出る。報告の詳細（API・事務所の画面）に「代理入力」（入力者・日時・理由）、作成の監査に理由と入力者を残す
- 運搬実績は運転者をマスタから選ぶ方式のため対象外（従来どおり入力者＝ログイン中の利用者）

### 1.5 アクセシビリティ（NFR-006）

- 全画面を axe（WCAG 2.1 A/AA）で検査し、違反を 0 件に: 補足文字・成功/注意の色を濃くした（文字と背景のコントラスト 4.5:1 以上）、手順表示の未到達の文字色
- 「本文へ移動」リンク（最初の Tab）とフォーカス枠を事務所・現場の画面に追加。ログイン画面の見出し（h1）を読み上げ対象に戻した
- 多要素認証・本人確認の画面: 見出しへのフォーカス移動、エラーは `role="alert"`、入力欄はラベル・`aria-invalid`・`autocomplete="one-time-code"`、ダイアログは `<dialog>`（Esc で閉じる、フォーカスは中）
