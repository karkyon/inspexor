## 2. 変更後の仕様

### 2.1 品番の明細（作業日報の品番・ロットの行）

| 項目 | 必須 | 規則 |
|---|---|---|
| 品番 | ○ | 選んだお客様の有効な品番 |
| 作業内容 | ○ | その品番の有効な作業内容 |
| ロットNo | 品番の設定による | 100文字まで。同じ品番・同じロットNo の行は1つ（ロットが違えば同じ品番を複数行に） |
| 作業数量 | ○ | 0〜999,999。工程ごとに数量を入れる品番（CHG-014 3.6）は仕上げ数量・検査数量 |
| 不良内訳 | 任意 | その品番の不良種別ごとの個数。合計は数量（工程ごとの品番は大きい方）以下 |
| その他の内容 | 任意 | 20文字まで（例: 色ハゲ、異物、サンプル）。不良種別「その他」がある品番で入力できる |

| 規則 | 内容 |
|---|---|
| 行数 | 1件に1〜20行 |
| 精算区分 | 1件の中の品番は同じ精算区分（個数／時間）。時間で精算する品番は1件に1品番（ロットごとの行は可）。作業者の時間を品番に分けられないため |
| 工程 | 1件の中の品番は同じ工程の設定（なし／仕上げ・検査） |
| 作業内容の表示 | 帳票の「作業内容」欄は、行の作業内容の名称を重複なしで「・」でつなぐ |
| 時間の扱い | 従事行（CHG-014）は報告全体で1つ。品番別・品番日別の集計では、報告の総作業時間を行の処理数量の比で分けた参考値（分の端数は最初の行）を使う |

入力画面（STEP2）は「品番を選ぶ → 作業内容 → ロットNo」を1行とし、「品番・ロットを追加」で行を増やす。1行だけのときは現行と同じ見た目にする。STEP4 は行ごとに数量・不良を入れる。

### 2.2 作業場所と移動回数

| 項目 | 内容 |
|---|---|
| 作業場所マスタ | isCustomerSite（お客様の工場）を追加（初期データ: 丸五ゴム工業 本社＝はい、三成興業 作業場＝いいえ） |
| 作業内容マスタ | defaultWorkLocationId（既定の作業場所）を追加。STEP2 で作業内容を選んだとき、作業場所が空なら既定の作業場所を入れる（変更可） |
| 作業日報 | moveCount（移動回数、0〜99、任意）。作業場所がお客様の工場のときだけ入力欄を表示 |
| 帳票 | 作業場所がお客様の工場なら、下部の欄を「移動回数（回）」「移動費（円）」とし、移動回数を印字する。それ以外は「運搬回数」「運搬費」（空欄、現行どおり）。移動費・運搬費は自動計算しない |
| 月次集計 | 品番日別に移動回数を出す |

16066-0003-01（触診確認、丸五ゴム工業 本社）は、品番一覧の備考は「移動費」、事務所用集計表の注記は「移動費込みの単価なので移動費はいらない」と食い違うため、移動回数を入れるかどうかを確認する（確認 N-8）。移動回数は入れても請求とは無関係（請求機能は本番無効）。

### 2.3 宛名（お客様担当者）

| 項目 | 内容 |
|---|---|
| お客様担当者マスタ | department（部署名、100文字まで、任意）を追加 |
| 帳票の宛名 | 「お客様名 御中」の下に「部署名　氏名 様」。明細の品番を日報の担当品番に含む有効な担当者が複数なら「氏名 様・氏名 様」と並べる（最大3名、部署が違えば部署ごとに改行）。0名なら空欄（現行どおり） |

品番一覧の担当者（賀門様・片山様・花村様・小橋様・三上様、安藤社長、鎌倉様）を初期データにする。高橋金属様の受領帳票にある井原様の扱いは確認 N-6。

### 2.4 その他の内容

不良種別「その他」の個数の横に、その他の内容（20文字まで）を入力できる。帳票の内訳は「その他 2（色ハゲ）」と印字する。月次集計の明細にも出す。

## 3. データの変更（詳細設計書 2.3・2.4）

| 対象 | 変更 |
|---|---|
| workReports/{id}/revisions（schemaVersion 2） | productId・workTypeId・lotNo・quantity・defects を items に置き換え。items: array(map) {lineNo, productId, workTypeId, lotNo, quantity, finishQuantity, inspectQuantity, defects: array(map){defectTypeId, quantity}, otherNote}。工程ごとの品番は quantity=null・finishQuantity/inspectQuantity に値、それ以外は quantity に値・finishQuantity/inspectQuantity=null。moveCount（int、null 可）を追加 |
| workReports（ヘッダ） | productIds（items の品番、重複なし）、quantity（処理数量の合計）、defectTypeIds（items の不良種別）は現行の項目のまま値の作り方を変える |
| current（月次集計用） | items: array(map) {productId, workTypeId, lotNo, quantity, finishQuantity, inspectQuantity, defectQuantity, allocatedMinutes}、moveCount、workLocationId |
| workLocations | isCustomerSite（bool、初期値 false） |
| workTypes | defaultWorkLocationId（id、null 可） |
| customerContacts | department（string(100)、null 可） |

Firestore の制約（配列の中に直接配列は置けない）は、items の中の defects が map の中の配列のため満たす（packages/docstore/src/values.ts の normalizeValue で確認）。

## 5. 帳票（DAILY_REPORT_V3、CHG-014 と同じ版）

| 欄 | 変更 |
|---|---|
| 宛名 | 部署名・複数の担当者 |
| 作業内容 | 行の作業内容の名称（重複なし） |
| 品番／ロットNo／作業数量／不良個数／内訳 | items の行ごと。最低4行。工程ごとの品番は数量を「仕上げ 454／検査 0」。内訳に「その他 2（色ハゲ）」 |
| 計 | 全行の数量・不良の合計（工程ごとの品番は仕上げ・検査それぞれの合計） |
| 下部 | お客様の工場なら「移動回数（回）」に値、「移動費（円）」は空欄。それ以外は「運搬回数」「運搬費」とも空欄 |

## 6. 月次集計（品番日別）

事務所用の集計表（品番ごと・日ごと）と同じ並びで、1品番ごとに月の全日の行を出す。

| 列 | 内容 |
|---|---|
| 日付・曜日 | 月の1日〜末日 |
| 有無 | その日に確定済みの作業日報があれば ○ |
| 数量 | 処理数量（工程ごとの品番は仕上げ・検査の2列） |
| 不良数 | 不良の合計 |
| 通常作業時間・割増作業時間 | 時間で精算する品番は報告の総作業時間（割増＝請求する時間外）。個数で精算する品番は参考値（配分した時間） |
| 作業時間 | 総作業時間（所内用、配分した参考値を含む） |
| 移動回数 | 作業日報の移動回数の合計 |
| 入力者 | 作業日報の報告者（複数なら「・」でつなぐ） |
