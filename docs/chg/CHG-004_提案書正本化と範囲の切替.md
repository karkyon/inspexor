## 1. 理由

仕様 v5.1 は初回ヒアリングの全体構想（請求計算・請求書・承認・自動メール）を範囲としていた。一方、顧客へ提示した提案書 `SK-2026-08-MINI`（2026-09-05、¥700,000 / 64人日）は範囲を「現場入力（作業・運搬）・日報PDF・月次集計」に絞り、次を**対象外**としている。

メール自動送信／請求書・請求書鏡の自動作成／運搬費の自動按分・請求金額への自動反映／時間外1.25倍の請求計算／複雑な請求条件マスタ／ICカード・バーコード入力／他システム連携／高機能ダッシュボード／承認ワークフロー／客先担当者ごとの送信設定

利用者の決定により**提案書を正本**とする。v5.1 の文書は、提案書と矛盾しない部分（技術基盤・入力規則・帳票生成・監査・セキュリティ）の詳細仕様として引き続き使う。

## 4. 技術構成の差（記録のみ）

提案書は Firestore＋Firebase Authentication 構成で月額 ¥数百〜1,500 程度と試算している。実装は v5.1 開発スタック定義書どおり Cloud SQL（PostgreSQL 16）＋自前認証で、G0〜G4 が稼働済み。Cloud SQL は常時課金のため、提案書の月額試算は再試算が必要（顧客説明は利用者が判断）。

## 5. 検証

- worker integration: `dailyMailEnabled` 未指定で帳票は GENERATED・SUBMITTED、mail job 0、送信 0
- documents API integration: メール無効で send は 404（`/action`）、outbox に副作用なし。配信 route の `disposition=inline` はブラウザ内表示、署名は引き続き必須
- web integration: 同じ業務日は作成日時の新しい順
- unit: logout 直後の遅延保存で端末下書きが復活しない（REQ-OFF-001。E2E で断続的に再現した不具合の修正）
- E2E: 作業の確定画面に「日報PDFをプレビュー／ダウンロード」、現場ホームから PDF 表示、事務所の PDF 再出力、Mailpit 受信 0 通
