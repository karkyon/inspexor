## 1. 有効化の設定（提案書の対象外機能）

| 環境変数 | 内容 | 既定 |
|---|---|---|
| `APPROVAL_ENABLED=true` | 承認ワークフロー（承認・差戻し・取消）と管理ダッシュボード | 無効 |
| `BILLING_ENABLED=true` | 請求計算・請求書（以降の CHG）。承認済みの実績が対象のため `APPROVAL_ENABLED` も必要 | 無効 |
| `DAILY_MAIL_ENABLED=true` | 日報メール自動送信（CHG-004 から） | 無効 |

文字列 `true` のときだけ有効。`GET /me` の `features` で画面に伝え、無効な機能は画面に出さない・API は 404（未定義の操作）。
開発環境は E2E のため `APPROVAL_ENABLED=true`。本番は無効のまま（有効化は利用者が判断）。

## 2. 承認ワークフロー（API-013 transitionRecord）

| 操作 | 状態 | 権限 | 理由 | 備考 |
|---|---|---|---|---|
| approve | SUBMITTED → APPROVED | OFFICE / ADMIN | 任意（コメント） | 現在の確定版（帳票作成済み）のみ |
| reject | SUBMITTED → REJECTED | OFFICE / ADMIN | 必須（1〜1000字） | |
| revoke | APPROVED → REVOKED | OFFICE / ADMIN | 必須 | 請求確定（BILLING_LOCKED）後は不可 |
| revise | CONFIRMED / SUBMITTED / REJECTED / REVOKED → DRAFT（新しい版） | OFFICE / ADMIN（D3）、**所有者は REJECTED / REVOKED の自分の報告のみ** | 必須 | APPROVED は取消してから |

- 状態・権限・理由の判定は domain `RECORD_TRANSITIONS`。version を照合して +1、Idempotency-Key で冪等、監査 `WORK_REPORT_APPROVE` / `_REJECT` / `_REVOKE`
- 直近の判断を header の `decision`（action・reason・at・actorId・revisionNo）に残し、一覧・詳細で返す。新しい版を作っても残る（履歴は監査）
- 帳票作成で SUBMITTED にした日時を header の `submittedAt` に記録（承認待ちの経過時間）
- RBAC: `transitionRecord` を owner 型（`roles(['OFFICE','ADMIN'], ownerAllowed)`）に変更。ロール外の利用者は handler が revise 以外を 403、service が所有者・状態を確認

## 3. 管理ダッシュボード（API-029 `GET /dashboard`、SCR-10）

OFFICE / ADMIN / AUDITOR。`APPROVAL_ENABLED` のときだけ（無効時 404。提案書の対象外「高機能ダッシュボード」）。

| 項目 | 定義 |
|---|---|
| 承認待ち | SUBMITTED の件数。うち `submittedAt`（旧データは更新日時）から24時間を超えた件数 |
| 本日の作業日報 | 業務日が今日（JST）の作業日報。確定済み（DRAFT 以外）と下書き |
| 本日の運搬 | 業務日が今日の確定済み運搬実績の件数と品番数 |
| 帳票の処理失敗 | 最終失敗（FAILED_FINAL）で、その報告の最新の帳票であるもの |
| 直近7日 | 業務日ごとの確定済み件数（作業・運搬） |
| 要対応 | 帳票の処理失敗・24時間超の承認待ち・差戻し中（新しい順に最大20件） |

検索は単一項目の条件だけ（複合索引の追加なし）。

## 4. 画面

| 画面 | 変更 |
|---|---|
| 事務所 左ナビ | 承認が有効なとき「ダッシュボード」（SCR-10）を表示 |
| 報告一覧（SCR-11） | 状態の絞込に 承認済・差戻し・取消 を追加（承認が有効なとき） |
| 報告詳細（SCR-12） | 直近の判断（承認・差戻し・取消と理由）、承認パネル（提出済: 承認／差戻し、承認済: 取消） |
| 現場ホーム（SCR-02） | 差戻し・取消された自分の報告に理由と「修正する」。修正内容を入力すると新しい版の下書きを作って入力画面に読み込む |

## 5. 検証

- domain: features（既定無効・'true' のみ・請求は承認が前提）、RBAC 29 operation
- web integration（`lib/approval/approval.itest.ts`）: 無効時 404・features、承認・差戻し（理由必須）・所有者の修正と再確定・取消（理由必須・SUBMITTED から 409）・version 競合・権限（AUDITOR／他人）・冪等、ダッシュボード（KPI・24時間超過・要対応・直近7日・処理失敗・schema）
- E2E（`e2e/approval.e2e.ts`）: 提出済 → ダッシュボード → 差戻し → 現場が修正して再確定 → 承認 → 取消
