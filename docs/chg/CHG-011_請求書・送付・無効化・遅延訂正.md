## 1. 変更内容

| No | 内容 |
|---|---|
| 1 | **請求書番号の表示を版付きに**: 保存は基本番号（`INV-202609-C1`）と版（revision）。画面・帳票・メール・API の表示は `INV-202609-C1-001`。請求 run の一覧・詳細の `invoiceNo` も版付き（CHG-009 の表示を変更） |
| 2 | **発行（API-023 issue）**: 確定済み（FINALIZED）の請求書から、鏡 `INVOICE_COVER_V1` と明細 `INVOICE_DETAIL_V1` の帳票 job を作る。発行時に発行元・発行日（JST）・支払期限を請求書へ記録（snapshot）。worker が両方の PDF を作ると、請求書と請求 run を ISSUED（発行済み）にする（SYSTEM の issue 遷移、監査 `INVOICE_ISSUED`）。PDF が失敗（FAILED_FINAL）したときは再発行できる（新しい job、`issueCount`+1） |
| 3 | **帳票**: 鏡＝宛名（御中）・請求書番号・発行日・対象期間・支払期限・発行元（住所・TEL/FAX・メール・登録番号）・ご請求金額・小計/消費税/合計・振込先。明細＝No・日付・品番/元実績・内容・数量・単価・倍率・金額、見出しは各ページに繰り返し、合計は最後に1回。除外した報告と0円の明細は載せない（固定費は0円でも載せる）。各ページ下に「請求書番号 n / 総ページ」 |
| 4 | **送付・再送（API-023 send / resend）**: 送付先＝お客様担当者のうち「請求書メール」が有効で、担当品番が空（全品番）か請求の品番を含む人。件名 `【請求書送付】YYYY年M月分 {請求書番号}`、添付は鏡・明細の2件。送信できたら請求書を SENT（送付済み）、請求 run も ISSUED→SENT。送付は1回だけで、2回目以降は再送（理由必須、`sendRevision`+1）。送付先0件は送信 job を FAILED_FINAL（`RECIPIENT_EMPTY`）で記録し、画面に理由を出す。監査に宛先・本文は残さない（件数のみ、SEC-017） |
| 5 | **無効化（API-023 void、理由必須）**: FINALIZED / ISSUED / SENT の請求書を VOIDED にし、請求 run も VOIDED（billing-status に FINALIZED/ISSUED/SENT→VOIDED を追加）。対象の報告は BILLING_LOCKED→APPROVED（record-status に SYSTEM の `billingUnlock` を追加）、期間の一意制約を解放 → 同じお客様・期間で作り直すと**版が1つ上がる**（`-002`）。送信中は無効化できない。この請求書を元にした有効な調整がある間も無効化できない（先に調整を取消）。この請求書に入っていた調整は未適用（PENDING）に戻る。確定済みの請求 run を請求画面（API-021 void）で取り消すことはできない（請求書の画面へ誘導、409） |
| 6 | **遅延訂正の調整（API-035〜037、DEC-004）**: 確定した請求書は変更しない。差額を「調整」（品番・内容・金額（0以外の整数円、負は値引き・返金）・理由・元実績（任意、その請求書の報告のみ））として登録し、**元の請求書の締め日の翌日以降に締める請求**の明細に `ADJUSTMENT` 行として入る。確定で APPLIED（適用先の請求書を記録）。未適用の調整は理由付きで取消できる。計算の後に調整が増減したら確定は 409 `SOURCE_CHANGED`（再計算が必要）。調整で合計が負になると既存の `NEGATIVE_INVOICE` 警告（要確認） |
| 7 | **画面 SCR-15 `/admin/invoices/{id}`**: 金額・支払期限、発行（PDF 作成中は3秒ごとに自動再読込）、PDF リンク（署名付き URL）、送付先・送付/再送・送付履歴、請求書に載る明細、調整の登録・一覧・取消、無効化。請求一覧・請求詳細の請求書番号から開く。メニューは「請求」を選択中にする。AUDITOR は参照のみ |
| 8 | **API 契約**: openapi `3.1.0-CHG-011`。`getInvoice`・`transitionInvoice` の応答を `InvoiceDetail` に、新規 `listBillingAdjustments`（API-035）・`createBillingAdjustment`（API-036、Idempotency-Key 必須）・`cancelBillingAdjustment`（API-037、Idempotency-Key 必須）。rbac は 37 operation |
