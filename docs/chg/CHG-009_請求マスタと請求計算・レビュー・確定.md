## 1. 有効化

| 環境 | 設定 |
|---|---|
| 開発 | `.env.local` に `APPROVAL_ENABLED=true`・`BILLING_ENABLED=true`（E2E で検証） |
| 本番 | 無効のまま（利用者の判断で有効化） |

無効のとき: 請求マスタ（`rates` / `transport-rules` / `fixed-charges`）と `/billing-runs` の API は未定義と同じ 404、画面のメニューにも出さない。

## 2. 請求マスタ（SCR-13）

- 単価ルール・運搬ルール・固定費ルールを Firestore（`rateRules` / `transportRules` / `fixedChargeRules`）で作成・更新・無効化できる
- 一意キーの代わりに **有効なルールどうしの適用期間の重なりを禁止**（PostgreSQL 版の `EXCLUDE ... WHERE (active)` と同じ）
  - 単価: 品番＋作業内容（空＝全作業）、運搬: 品番＋作業内容＋運搬区分、固定費: 品番＋費目
- 適用終了日 ≧ 適用開始日、割増倍率 ≧ 1、作業内容は同じ品番のもの（422）
- マスタ変更の影響 preview（`affectedOpenBillingRunCount`）: 確定前の請求 run のうち期間が重なるものを数える（ルールはその品番のお客様、休日は全お客様）

## 3. 計算エンジン（`packages/domain/src/billing-engine.ts`）

請求・運搬費計算完全仕様書 v5.1 に従う純粋関数。入力（承認済み実績の現在版・ルール・品番）だけから明細・警告・税を作る（現在のマスタを参照しない）。

| 区分 | 計算 |
|---|---|
| 作業（個数） | 数量×単価 |
| 作業（時間） | 通常人分/60×単価 と 割増人分/60×単価×割増倍率 を**別明細**にして、明細ごとに四捨五入 |
| 単価ルールの選択 | 品番＋作業内容＋作業日で 1 件（作業内容が一致するルールを優先、無ければ全作業）。0 件 `RULE_NOT_FOUND`、複数 `RULE_AMBIGUOUS`（明細を作らない） |
| 運搬 PER_TRIP | 金額×運搬回数 |
| 運搬 ALLOCATED | **GAP-016 の解消: 運搬ルールが ALLOCATED の品番を按分対象（allocation_eligible）とする**。運搬費（CHG-004 D2: 運搬報告1件に1金額）が入力済みならその金額を、未入力なら按分グループごとのルール金額（1便）を、対象 distinct 品番で按分（q=floor(fee/n)、余り r を品番コード昇順の先頭 r 件へ +1）。ルール金額のときは運搬回数を掛ける。グループ内で金額が違えば `RULE_AMBIGUOUS` |
| 運搬 NONE | 0（明細なし） |
| 運搬 MONTHLY_FIXED・固定費 | 請求期間に重なる有効なルールを期間に 1 回。同じ品番（固定費は費目）に複数重なれば `RULE_AMBIGUOUS` |
| 按分対象なし | 運搬費が入力済みで按分対象の品番が無い → `NO_ALLOCATION_TARGET` |
| 税 | 小計×10% を四捨五入、合計＝小計＋税。合計が負なら `NEGATIVE_INVOICE`（確定不可） |

billing-golden.json の 14 件（G-TIME は日報の工数計算で検証済み、G-QTY/G-ROUND/G-BILL/G-ALLOC/G-TAX はエンジンの明細として再現）を `billing-engine.test.ts` で検証する。

## 4. 請求 run（SCR-14 / API-019〜021・API-034）

| API | 内容 | 権限 |
|---|---|---|
| API-034 `GET /billing-runs` | 一覧（期間の新しい順。お客様・状態で絞込） | OFFICE / ADMIN / AUDITOR |
| API-019 `POST /billing-runs` | お客様＋締め日（periodEnd）で作成。請求期間は前締め翌日〜当締め日（31＝月末、その月に無い締日は月末）。締め日でなければ 422、同じお客様・期間は取消以外 1 件（409、既存の run ID を返す） | OFFICE / ADMIN |
| API-020 `GET /billing-runs/{id}` | 合計・明細・警告・計算版の一覧（`?calcVersion=n` で過去の計算版） | OFFICE / ADMIN / AUDITOR |
| API-021 `POST /billing-runs/{id}/{action}` | `calculate` / `review` / `finalize` / `void`（Idempotency-Key 必須） | OFFICE / ADMIN |

状態遷移（domain `billing-status.ts`。★は本 CHG で追加）:

```
OPEN ─calculate→ CALCULATING ─(警告なし)→ CALCULATED ─finalize→ FINALIZED
                              └(警告あり)→ NEEDS_REVIEW ─review→ REVIEWED ─finalize→ FINALIZED
★ CALCULATED / NEEDS_REVIEW / REVIEWED ─calculate→ CALCULATING（再計算: 新しい計算版。旧結果は残す）
★ OPEN / CALCULATED / NEEDS_REVIEW / REVIEWED ─void→ VOIDED（確定前の取消。理由必須。同じ期間で作り直せる）
```

- **計算**: 承認済み（APPROVED）の現在版だけが対象。期間内の未承認の報告数を `unapprovedCount` で示す（請求に含まれない）。計算は request 内で同期に行い、結果は `billingRuns/{id}/calcs/{calcVersion}`（警告・処置・対象の版）と chunks（明細・計算入力の JSON）に保存。run hash（明細・警告・合計の canonical JSON の SHA-256）・rule hash・input hash を記録。計算中に止まった run は 10 分後に計算前の状態から再計算できる
- **レビュー**: すべての警告に処置（`ACCEPT`＝そのまま／`EXCLUDE`＝その報告を請求から除外）と理由が必要。報告に結び付かない警告（期間ルールの重なり等）は除外できない（ルールを直して再計算）。除外した報告の明細を除いて合計を再計算する。CORRECT_SOURCE は「元データ・ルールを直して再計算」で表す
- **確定**: 計算に使った版が今も承認済みの現在版か、期間内に新しく承認された報告が無いかを照合し、違えば 409 `SOURCE_CHANGED`（再計算を促す）。請求書（`invoices/{id}`: 請求書番号 `INV-YYYYMM-お客様コード`・版・お客様 snapshot・合計・計算版・run hash）を作り、対象の報告を `BILLING_LOCKED`（以後の修正・取消は不可）にする。除外した報告は承認済みのまま
- 監査: `BILLING_RUN_CREATE` / `BILLING_RUN_CALCULATE` / `BILLING_RUN_CALCULATED` / `BILLING_RUN_CALCULATE_FAILED` / `BILLING_RUN_REVIEW` / `BILLING_RUN_FINALIZE` / `BILLING_RUN_VOID`

## 5. 画面

- `/admin/billing`: 請求の一覧と「請求を計算する」（お客様・請求月 → 締め日を表示 → 作成して計算）
- `/admin/billing/{id}`: 合計（小計・税・合計・hash）、要確認（処置の選択・理由 → レビューを完了）、明細（日付・元実績・品番・区分・数量/工数・単価・倍率・金額、除外は取消線）、計算版の切替、再計算・確定・取消
- 仕様の Route `/admin/billing/{period}` は、同じ期間に取消済みの run が残りうるため run ID にした
- 左ナビ「請求」、マスター管理に「単価ルール・運搬ルール・固定費」（請求機能が有効なときだけ）
